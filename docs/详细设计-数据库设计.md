## 2. 存储选型：为什么用三个存储

| 存储 | 存什么 | 为什么不用一个 |
|---|---|---|
| **MariaDB**（`insurance`）| 业务数据：作品集、技能、知识父块 | 关系型、事务、SQL 查询方便 |
| **PostgreSQL**（`agentdb`）| LangGraph 检查点（会话记忆）| 官方 `PostgresSaver` 的表结构固定，独立库避免污染业务表 |
| **Milvus Lite**（文件）| 知识子块向量 | 向量检索需要专用索引（COSINE + AUTOINDEX）|

### 设计取舍

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 全部塞进 MariaDB | 一个库省事 | 无向量检索；检查点表与业务表混在一起 | ❌ |
| **职责分离（当前）** | 各司其职、可独立迁移/扩容 | 需要维护三套连接 | ✅ 采用 |

## 3. 概念模型（ER）

```
┌─────────────────────┐
│      projects       │   作品集（独立实体）
│  id / name / ...    │
└─────────────────────┘

┌─────────────────────┐
│  knowledge_parents  │   知识父块（一个章节/小节）
│  id / title / ...   │
└──────────┬──────────┘
           │ 1 : N（逻辑关联，跨库，无外键）
           │   parent_id
┌──────────▼──────────┐
│ knowledge_children  │   知识子块（Milvus，存向量）
│  id / parent_id /   │
│  content / vector   │
└─────────────────────┘

┌─────────────────────┐
│      products       │   课程遗留（保险产品）
└─────────────────────┘

┌─────────────────────┐
│ conversations       │   课程遗留（Day04 会话）
│ messages            │
└─────────────────────┘
```

**关键关系**：`knowledge_parents 1 —— N knowledge_children`，通过 `parent_id` 关联。
两者**跨存储**（MariaDB ↔ Milvus），因此**不建数据库外键**，由应用层保证一致性。

## 4. 表结构（详细设计）

### 4.1 `projects` — 作品集

**用途**：首页作品卡片、作品集页、Agent 的 `search_projects` 工具。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | INT | PK, AUTO_INCREMENT | 主键 |
| `name` | VARCHAR(100) | NOT NULL | 项目名 |
| `summary` | VARCHAR(255) | NOT NULL DEFAULT '' | 一句话简介（卡片显示）|
| `description` | TEXT | NOT NULL DEFAULT '' | 详细介绍（弹窗显示）|
| `tech_stack` | VARCHAR(255) | NOT NULL DEFAULT '' | 技术栈，**逗号分隔** |
| `github` | VARCHAR(255) | NOT NULL DEFAULT '' | GitHub 链接 |
| `demo` | VARCHAR(255) | NOT NULL DEFAULT '' | 在线 Demo 链接 |
| `bvid` | VARCHAR(64) | NOT NULL DEFAULT '' | B 站 BV 号（空=无视频）|
| `cover` | VARCHAR(255) | NOT NULL DEFAULT '' | 封面图路径 |
| `sort_order` | INT | NOT NULL DEFAULT 0 | 排序（小的在前）|

**DDL**：

```sql
CREATE TABLE projects (
  id          INT           NOT NULL AUTO_INCREMENT,
  name        VARCHAR(100)  NOT NULL,
  summary     VARCHAR(255)  NOT NULL DEFAULT '',
  description TEXT          NOT NULL,
  tech_stack  VARCHAR(255)  NOT NULL DEFAULT '',
  github      VARCHAR(255)  NOT NULL DEFAULT '',
  demo        VARCHAR(255)  NOT NULL DEFAULT '',
  bvid        VARCHAR(64)   NOT NULL DEFAULT '',
  cover       VARCHAR(255)  NOT NULL DEFAULT '',
  sort_order  INT           NOT NULL DEFAULT 0,
  PRIMARY KEY (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```

**索引**：

```sql
CREATE INDEX idx_projects_sort ON projects (sort_order, id);
```

**设计说明**：

| 决策 | 理由 |
|---|---|
| `tech_stack` 用逗号字符串 | 技术栈是展示用的轻量列表，无需单独关联表；Pydantic 输出时拆成 `tech: list[str]` |
| `bvid` 独立字段 | 空字符串表示"该项目无视频"，前端据此决定是否渲染播放器 |
| `sort_order` 而不是按 id | 允许手动调序，不必删了重插 |
| `description` 用 TEXT | 详情可能几百字 |

### 4.2 `knowledge_parents` — 知识父块

**用途**：RAG 父子块检索——从 Milvus 命中子块后，按 `parent_id` 取回完整父块内容。

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | VARCHAR(128) | PK | 形如 `Linux学习笔记D5-Agent基础-p2` |
| `title` | VARCHAR(255) | NOT NULL | 章节标题（`h2` 或 `h1`）|
| `content` | TEXT | NOT NULL | 完整章节内容 |
| `source` | VARCHAR(255) | NOT NULL | 源文件名 |

**DDL**：

```sql
CREATE TABLE knowledge_parents (
  id      VARCHAR(128) NOT NULL,
  title   VARCHAR(255) NOT NULL,
  content TEXT         NOT NULL,
  source  VARCHAR(255) NOT NULL,
  PRIMARY KEY (id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE INDEX idx_kp_source ON knowledge_parents (source);
```

**设计说明**：

| 决策 | 理由 |
|---|---|
| 主键用 VARCHAR 而非自增 | `id` 由构建脚本生成（`{slug}-p{序号}`），可复现、可追溯 |
| 无 `created_at` | 知识库整体重建，时间无意义 |

---

### 4.3 Milvus `knowledge_children` — 知识子块（向量）

**用途**：向量检索入口。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | VARCHAR(128) PK | 形如 `{parent_id}-c0` |
| `parent_id` | VARCHAR(128) | 指向 MariaDB 的父块 |
| `content` | VARCHAR(8000) | 子块文本（约 400 字）|
| `vector` | FLOAT_VECTOR(1024) | DashScope `text-embedding-v4` 输出 |

**索引**：`AUTOINDEX`，度量 `COSINE`。

**设计说明**：

| 决策 | 理由 |
|---|---|
| 子块 400 字 + 重叠 50 | 检索粒度合适：太小丢上下文，太大噪声多 |
| 向量维度 1024 | DashScope v4 默认维度，换模型需整体重建 |
| 父子分离存储 | 子块小利于检索精度；父块大利于上下文完整性 |

### 4.4 PostgreSQL — LangGraph 检查点

由 `PostgresSaver.setup()` 自动创建，**不手工设计**：

| 表 | 用途 |
|---|---|
| `checkpoints` | 每步状态快照 |
| `checkpoint_blobs` | 大的二进制状态块 |
| `checkpoint_writes` | 待写入 |
| `checkpoint_migrations` | 版本迁移 |

**关联方式**：`thread_id` = 前端生成的会话 ID。

## 5. 设计规范

| 项 | 规范 |
|---|---|
| 命名 | 表名/字段名 **snake_case**，表名复数 |
| 主键 | 业务表 `INT AUTO_INCREMENT`；知识库用 `VARCHAR`（可复现）|
| 字符集 | `utf8mb4`（支持 emoji/中文）|
| 时间字段 | 暂用 Python 侧 `default=datetime.now`（MariaDB 5.5 不支持 `DEFAULT now()`）|
| 外键 | **不建**（跨存储无法建；同库也由应用层保证，避免级联删除风险）|
| 软删除 | 暂不做（个人项目，直接删）|
| 大字段 | 业务表用 `TEXT`；向量表 `VARCHAR(8000)` |

## 6. 数据流

### 写入（离线）

```
scripts/build_knowledge_base.py
  knowledge/*.md
    → MarkdownHeaderTextSplitter（按 h1/h2 切父块）
    → RecursiveCharacterTextSplitter（400 字切子块）
    → DashScope embedding
    → Milvus: knowledge_children
    → MariaDB: knowledge_parents
```

### 读取（在线）

```
用户提问
  → 子块向量化（同一模型）
  → Milvus 检索 top-5 子块
  → 去重取 parent_id
  → MariaDB 查父块内容
  → 拼上下文给 LLM
  → 返回答案 + 引用列表
```
